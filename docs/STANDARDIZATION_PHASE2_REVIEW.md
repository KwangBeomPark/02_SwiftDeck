# SwiftDeck 배포·업그레이드 정비 2단계 검수

기준일: 2026-10-07. 기존 1.4.1 배포물·태그·설정·설치 식별자는 유지합니다. 이번 변경은 다음 배포 버전부터 적용할 소스이며 실제 서명·설치·게시를 수행하지 않았습니다.

## 반영한 동작

- `build.ps1`은 `build/`, `dist/`, `out/` 내부의 로컬 출력만 허용하며 공식 `release/`와 경로 연결점 쓰기를 차단합니다. 테스트 생략 여부, 커밋, 소스·설치 설계·자산·테스트의 내용 해시 및 미커밋 상태를 `build-provenance.json`에 기록합니다. `-ExecutableOnly`는 서명 파이프라인에 필요한 실행 파일만 만듭니다.
- `sign.ps1`은 고유한 `build/release-stage-*`에서 테스트를 통과한 EXE를 빌드합니다. EXE 서명·검증 → ZIP 생성 및 내부 바이트 검증 → 서명된 EXE로 설치 파일 생성 → 설치 파일 한 번 서명·검증 → 별칭 복사 순서입니다. 기존에 사용하던 잘못된 `build.ps1 -SkipSigning` 호출과 개인별·다른 프로젝트 도구 경로를 제거했습니다. 인증서 저장소를 명시적으로 확인하고 선택한 인증서가 없으면 다른 인증서로 대체하지 않습니다. 시스템 서비스는 시작하지 않습니다.
- `-SkipBuild`는 `build-provenance.json`의 버전·커밋·현재 소스 해시·테스트 성공·EXE 해시가 모두 일치할 때만 사본을 재사용합니다. 테스트 생략 빌드는 공식화하지 않습니다.
- `ReleaseSafety.ps1`은 서명·타임스탬프·서명자 기록, 네 파일의 정확한 이름·크기·SHA-256, 체크섬 목록, ZIP의 유일한 EXE 바이트 및 설치 별칭 동일성을 검사합니다.
- 공식 반영 전 전체 검증을 마치며, 기존 버전 이름의 EXE/ZIP 바이트가 다르면 교체하지 않습니다. 새 버전 반영 시 이전 `release/`는 `build/release-history/<시간-GUID>`에 통째로 보존한 뒤 새 디렉터리를 이동합니다. 이동 실패 시 이전 폴더를 복원합니다. 복원 자체가 실패하면 보존 경로를 오류로 알립니다. 이는 실행 중단/전원 상실까지 원자적인 교체를 보장하는 방식은 아닙니다.
- `publish.ps1`은 빌드하지 않으며 깨끗한 main·일치하는 커밋/소스 근거·전체 서명 검증이 필요합니다. 기존 태그를 이동·삭제하거나 기존 자산을 덮어쓰지 않습니다. `-Resume`은 같은 커밋의 기존 릴리즈에서 SHA-256 digest/크기까지 일치하는 파일은 유지하고 누락 파일만 추가합니다. 원격 digest가 없거나 다르면 중단합니다. draft와 공개 릴리즈를 전체 페이지 목록에서 조회하고 새 게시 뒤에도 원격 digest/크기를 재검증합니다. 실제 게시는 명시적인 실행 또는 `sign.ps1 -Publish`일 때만 가능합니다. `-AllowUnsigned`는 거부합니다.
- `release.ps1 -SkipSigning`은 `dist/`에만 출력합니다. 미서명 게시 조합은 거부합니다.

## 설치·업그레이드

`AppId`, `SwiftDeck.exe`, 기본 설치 위치와 사용자 설정 계약은 유지합니다. `UsePreviousAppDir=yes`를 명시하여 같은 AppId의 이전 사용자 지정 설치 위치를 따릅니다. 컴파일러의 기본 출력은 공식 폴더가 아닌 `build/installer`입니다.

`CloseApplications=yes`로 Windows Restart Manager가 정상 종료를 요청할 기회를 유지합니다. 첫 EXE 복사 직전 `EnsureUpgradeReady`가 기존 EXE의 배타적 쓰기 가능 여부를 확인하며, 종료 거부·잠금·권한 오류가 남으면 설치를 차단합니다. 강제 종료나 기존 앱 전체 사전 제거는 하지 않습니다. `RestartApplications=no`로 이전 프로세스 자동 재시작을 피하고, 설치가 완료된 후 선택한 경우 `[Run]`으로 새 EXE를 실행합니다. 기존 고정 이름 EXE는 같은 위치에서 교체하므로 버전별 구형 EXE를 별도로 삭제하지 않습니다.

파일 잠금 검사는 프로세스가 전혀 없다는 완전한 증명이 아닙니다. 실제 실행 중 업그레이드·종료 거부·복사 실패·취소·재부팅 경로와 제거 후 `UserSetting` 및 Roaming 설정 보존은 Windows 실사용 검증 단계에 남습니다. 이전 바로가기·Run 키 정리 동작은 유지하며, 설치 실패 시 일부 바로가기는 이미 정리될 수 있습니다.

## 검증 근거

- `Test-ReleaseSafety.ps1`: 45개 assertion 통과. 커밋/소스 불일치, 테스트 생략·미커밋 게시, 미서명·타임스탬프 누락·서명자 변경, 바이트 변조, 서로 다른 설치 별칭, 오래된 ZIP, 체크섬 개수, 원격 digest 불일치, 기존 버전 충돌, 검증 실패·이동 실패 후 공식 원본 복원, 이전 버전 아카이브 보존 및 위험한 진입점 차단을 확인했습니다. 서명은 격리된 테스트용 mock이며 인증서 서명 증명이 아닙니다. 테스트 전후 실제 공식 파일 해시는 동일합니다.
- 도구 탐색 5개 assertion 및 기존 AHK 회귀 6개 suite, 정적 검사 통과.
- 공백을 포함한 고유 `build/phase2 verification <GUID>`에서 실제 Ahk2Exe 및 Inno Setup 6.7.3 미서명 빌드 성공. 새 설치 정의/잠금 callback 컴파일, 설치 별칭 SHA-256 동일, ZIP 패키징을 확인했습니다. 설치 파일은 실행하지 않았습니다.
- Antigravity `gemini-3.8-flash-high` / effort `high`로 구현 초안을 요청하고 Codex가 독립 검수하여 적용했습니다. 두 번째 전체 소스 Gemini 검수 요청은 제한 시간 내 최종 응답을 내지 못했고 결과로 사용하지 않았습니다. 별도 Codex 교차 검수의 서명 메타데이터 누락은 단일 writer로 수정했습니다. 허구 mutex, 재사용 빌드에 테스트 성공을 임의로 부여하는 코드, 기존 잘못된 빌드 인자 및 위험한 임시 폴더 정리는 채택하지 않았습니다.

실제 SimplySign 서명/타임스탬프, ZIP 내부 Windows 신뢰 확인, 실행 중 구버전 설치·제거·실패 복구, GitHub 게시 후 원격 바이트 일치는 완료되지 않았습니다. 버전·커밋을 준비한 후 사용자 인증서 세션에서 별도 검증해야 합니다.
